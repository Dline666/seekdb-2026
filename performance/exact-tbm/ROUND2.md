本轮实际改动：

- 为量化距离展开补充随坐标幅度、维数变化的绝对舍入误差上界。原 d7 和首轮 e908 在300条相同 VECTOR(512)、分量7722174976、主键逆序插入的用例中返回173…182，正确答案是1…10。新版本保留候选的精确距离验证，并修复这种错误剪枝。
- 用负的行偏移表示删除状态，释放合法的最小 BIGINT 主键；覆盖过滤、删除、重用槽位、回滚和重启。对可能溢出 int32 累加器的维数禁用整数预过滤，使用精确扫描。
- 所有扫描路径共用32字节的已折叠量化常量，删除每行重复保留的24字节参数；大约每100万行减少22.9MiB常驻派生数据。无预过滤路径不再分配查询量化码。
- 等值分类分两遍统计并一次分配槽位数组，减少扩容；预算计入分组、字符串和槽位，并让各表共享派生索引预算。容量超限时释放可选结构或回退到精确扫描；修改数据会清理旧缓存。map成本仍是估计值，预算也不覆盖权威行表、日志映射、暂时分配和整个进程，不能视为严格RSS上限。

最终候选来自实际 Docker 镜像 `seekdb-exact:folded-safe`，镜像ID为 `sha256:17fdac5104e445d7b1bc7f02297c5180493d891f9211e5a68197a3507f7d7b90`。所有表格版本均用该镜像构建阶段的 Ubuntu Go 1.22.2、CGO关闭及相同构建参数编译。`release-safe` 是从镜像提取的同一个可执行文件；[binary-sha256.txt](results/round2/binary-sha256.txt)记录二进制摘要。首轮候选为 e908d84；它仍有上述正确性缺陷，只用于历史性能对照。

运行环境为 Intel Core Ultra 5 125H / AVX2、WSL ArchBench、ext4专用数据设备。性能过程在独立cgroup内执行镜像中的程序，2 CPU / 2GiB / 128 PID、无swap，驱动在cgroup之外。实际Docker协议验证另行运行，避免将逐请求的Docker客户端开销混入性能指标。每个阶段独立启动、独立数据目录；B/M覆盖装载、预热、测量及退出写回。T包含协议往返、查询输出或写入持久化；真值计算及响应解码在计时外。默认规模5轮、扩展规模3轮，版本交错执行。

本地综合指标严格使用规则的 `T:B:M=0.6:0.2:0.2`、`写入:查询=1:2`、`f(R)=R/(1+R)`，以及1毫秒/1MiB平滑常量。固定参考版本前3轮各指标中位数，每轮分别计算E后取中位数。这里的参考版本只为本地比较，不是平台固定基线。
